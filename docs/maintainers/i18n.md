# Languages

The panel ships six interface languages, all with the same strings:

| Code | Language |
|---|---|
| `en` | English (the source and the default) |
| `es` | Español |
| `pt` | Português |
| `fr` | Français |
| `de` | Deutsch |
| `it` | Italiano |

Only interface text is translated. Code, logs and the API's error codes stay in
English.

## How a locale is chosen

The language menu calls the `set-locale` Server Action, which checks the session
and then validates the value against the list below. It stores the choice in the
`locale` cookie (HttpOnly, Secure, SameSite=Lax, one year). On each request
`src/i18n/request` reads the cookie, and anything that is not exactly a shipped
code (`ES`, `pt-BR`, `../en`, an empty value) falls back to English. The root
layout puts the locale in `<html lang>`, and `global-error.tsx`, which cannot use
the provider, reads the same cookie.

## One list

`SUPPORTED_LOCALES` in `internal/src/i18n/locales/index.ts` is the only list of
codes. The menu, the schema that validates the action, the cookie resolution,
the message loader, the unit tests and the `set-locale` end-to-end scenario all
read it; nothing else spells a code out. `LOCALE_NAMES` next to it holds each
language's own name, shown in the menu as is.

Dates and numbers go through `useFormatter` of `next-intl`, which uses the
active locale's `Intl` rules. Never format them by hand.

## Messages

One JSON file per namespace under `internal/src/i18n/messages/<locale>/`, the
same thirteen files in every locale. English is the source: its keys and its
`{placeholder}` and ICU plural structure are what every other locale is held to.

`bun test` fails when a locale is missing a key, has one more, uses a different
placeholder, or changes the shape of a plural or select (its arguments and arm
selectors, read by `i18n/messages/test-support/icu`). It also fails on an empty
message and on an apostrophe next to a brace, which ICU reads as a quote and
which would swallow the argument: write `’` in the languages that have
elisions.

Terms used in the mail vocabulary, so a new locale stays consistent: queue,
delivery, suppression (the list of addresses the server will not send to),
mailbox, domain.

## Adding a language

1. Add the code to `SUPPORTED_LOCALES` and its own name to `LOCALE_NAMES` in
   `internal/src/i18n/locales/index.ts`.
2. Create `internal/src/i18n/messages/<code>/` with the thirteen namespace files,
   copying `en/` key for key.
3. Import its `error.json` in `internal/src/app/global-error.tsx` and add it to
   `CATALOGS`; the type is keyed on `Locale`, so `tsc` reminds you.
4. Update the tests that name the list literally (`i18n/locales/index.test.ts`)
   and the table above and the README.
5. Run `bun test`, `bun run typecheck`, `bun run lint`, build and
   `scripts/e2e/run.sh set-locale`, then look at `/login` and `/app/accounts` in
   the new language with the console open: no missing message, no CSP violation,
   and axe without violations.
